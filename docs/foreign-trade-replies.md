# 外贸回复功能开发与交付说明

## 1. 目标与首版范围

WA Web Translate 为中国卖家与墨西哥客户提供商品、支付、物流和信任说明的回复辅助。业务回复目标固定为西班牙语；现有双向翻译设置和聊天记录译文功能保留。

首版六个顶部横向 Tab：**设置、商品、支付方式、物流、信任与保障、自动回复**。窄窗口可横向滚动标签。商品及业务配置只保存到当前浏览器的扩展存储。不做 Excel/批量导入、SKU 字段、多设备同步、订单定制或售后 Tab。

状态：功能代码已完成；可通过生产构建生成 `dist/`。真实 WhatsApp 页面中的后台新消息、原生图片预览和图片发送需按本文最后的步骤验收。模拟环境结果不能代替真实账号兼容性验收。

## 2. 页面设计与填写规则

### 设置

保留现有母语、对方语言、AI 服务商、模型、API Key、翻译风格及启用翻译功能。一般聊天仍遵循这些设置；外贸业务回复使用固定西语目标。适合当前业务的聊天语言配置为中文与西班牙语。停用翻译插件后，业务消息处理也暂停。

### 商品

列表上方为本类别自动回复开关、所有商品统一使用的内容语言、搜索和新建入口。每行显示封面缩略图、名称、型号、标准售价与币种、启用关键词数量、商品启用状态及编辑/删除按钮；列表不展示描述。

编辑页从上到下：

| 区域 | 内容与行为 |
| --- | --- |
| 商品名称 | 必填，首版不单设 SKU。保存同名商品时提示重复，用户可取消或继续保存。 |
| 型号、商品介绍 | 可填写，介绍只在编辑页面展示。 |
| 商品图片 | 从本机选择 JPG、PNG、WebP、GIF；每商品最多 6 张，每张不超过 1.5 MB。支持缩略图预览、删除、前后排序、指定封面。 |
| 标准售价、币种 | 售价必填，非负数。支持 USD、MXN、CNY、EUR。仅用于人工报价参考。 |
| 中文触发关键词 | 标签、添加输入框、AI 建议按钮及待确认建议。 |
| 商品启用 | 停用商品保留资料，但不参与匹配。 |
| 底部操作 | 取消、保存商品。图片读取期间禁用保存；保存失败保留表单并提示。 |

商品编辑内容和关键词在点击保存后生效。切换 Tab 时，未保存的商品编辑会先提示。列表搜索名称和型号；同一条商品代表一个具体型号或规格。所有商品共用一项内容语言，不逐商品识别语言。

### 支付方式

顶部放本类别自动回复开关，其下为中文关键词、回复内容语言、收款方式列表和添加按钮。

- 首次配置预置“银行转账”（默认）与“OXXO”（备用）；**说明正文均为空**，由用户填写。支持新增、删除、修改、启停和指定默认方式。
- 每种方式维护名称与一段收款说明，账号、银行、支付步骤等写在这段说明里。
- 普通付款问题使用已启用且已填写的默认方式；默认内容未填时提示补充，不擅自改用备用方式。
- 默认方式不方便时，先列出已填写、已启用的备用方式名称，客户选定后发送对应完整收款说明。
- “不方便”“其他方式”等泛泛表达只有在最近已发送的付款回复上下文中才适用；该上下文保留 15 分钟并在刷新后继续有效。未发送的付款草稿不会建立此上下文。
- 选择支付方式名称也可参与匹配；预置 OXXO 和银行转账关键词可启停。新增名称应使用客户可识别的名称，并按需补充对应关键词。
- 留空或停用的方式不会提供给客户。

### 物流

顶部放自动回复开关，下面为中文关键词、内容语言、可编辑物流字段和最终回复预览。

| 字段 | 首次默认值 |
| --- | --- |
| 发货后预计送达时间 | 9–12 天 |
| 物流方式 | 中国物流 |
| 发货安排 | 通常当天下午安排发货，节假日可能顺延。 |

命中物流问题后，回复包含这三项。单号、订单截图和物流图片由卖家在 WhatsApp 手动发送，不预录入该页面。选择中文时，预览通过“生成西语预览”按钮按需翻译；西语内容直接预览。

### 信任与保障

页面放自动回复开关、中文关键词、内容语言、付款与发货说明、可选客户群邀请链接、是否附带邀请和回复预览。

默认正文：**收到付款后我们会先核实，确认到账后才会安排发货。** 不加入售后承诺，也不重复物流时效和发货安排。

启用群邀请后，拼接顺序为：付款核实说明 → 西语客户体验群介绍与加入隐私说明 → 单独一行群链接。客户自行点击加入。链接必须是有效的 HTTPS WhatsApp 群邀请链接；无效时提示补充，停止这类发送。付款凭证、实际单号和截图仍由卖家手动发送。

### 自动回复

该 Tab 只放全局开关、风险确认、一键暂停及分类状态汇总；分类开关分别放在商品、支付、物流、信任各自页面。

- 全局与四个分类开关首次都关闭，默认使用草稿。
- 每次开启全局开关均提示：“自动发送消息可能导致 WhatsApp 限制账号。确认了解此风险并启用自动回复吗？”取消时保持关闭。
- 全局和对应分类均开启，且配置完整，才允许自动发送。
- 分类汇总区分草稿确认、等待全局开启、自动回复生效。
- 一键暂停关闭全局开关，保留分类偏好。准备图片期间也会在实际发送前复核开关与配置。
- 价格相关、多商品、多类别合并或内容不完整的回复始终由人工处理。

## 3. 关键词编辑

所有类别用同一套标签操作：绿色为启用、灰色为停用；点击标签切换，铅笔修改，独立 × 删除。输入后按回车或点击添加；重复词提示。停用保留词条，重新启用后参与匹配。

商品新建时带常见信息、图片、型号、报价问题关键词，用户可修改。点击“根据商品资料生成建议”才调用已配置模型，将商品名称、型号和介绍作为数据提交；不因每次编辑自动调用。建议默认为勾选状态，必须点击“加入已启用关键词”并保存商品才生效。生成过程中商品资料改变时，丢弃过时建议。

支付、物流和信任类别预置中文常用词，无需模型生成；用户可自行增删改和启停。泛泛付款词受付款对话上下文限制。

匹配规则：对客户**新消息的中文译文**进行匹配；中文按短语，拉丁字母按完整词，忽略大小写并规范化全半角。单词命中一次即可产生候选；同一规则多个词命中只生成一份回复。不对客户原文再跑一套规则，不读取引用消息的正文来触发。

## 4. 翻译与拼接

1. 客户消息先得到中文译文，再进行本地关键词匹配。能用既有中文翻译缓存时复用；相同请求共享进行中的翻译，不为关键词另调用模型。
2. 每个业务模块由用户明确选择源语言。中文内容翻成西语，西语内容原样使用，不调用语言识别。商品源语言全局统一。
3. 商品名称、型号和价格数字保留原样，使用固定西语字段标题；介绍单独按商品内容语言处理。
4. 多类别回复按商品、支付、物流、信任顺序，以空行拼接成一个人工草稿。客户群链接不经过翻译。
5. 中文固定回复按文本、源/目标语言、服务商、模型和翻译风格缓存；修改这些内容后使用新的缓存键。
6. 已准备的西语草稿及其在原生输入框中的编辑内容注册为本聊天的业务草稿；发送钩子不会再翻译一次。编辑时应保持西语。

## 5. 新消息、跨聊天与发送流程

MAIN 页面适配器订阅消息集合的新模型事件，按消息 ID 中的真实聊天归属记录。仅接收本次页面运行中的新鲜客户私聊文本/图片说明；初始化已存在的模型、自己发送的内容、历史加载、群聊和无文字媒体不会触发。它不通过点击或切换聊天来代发。

### 默认草稿

B 来新消息、用户当前在 A 时，只保存 B 的待处理记录。打开 B 后才翻译匹配并生成 B 的草稿；A 界面不出现 B 的草稿。

- 原生输入框为空：插入回复；商品有图时尝试打开封面图的原生媒体预览，并写入说明文字，等待用户检查与发送。
- 输入框已有文字：不覆盖，辅助栏保留草稿并提供插入/复制操作。
- 图片预览失败：保留草稿、显示失败原因，允许手动附图或复制文字；不会自行发送。
- 辅助栏可查看完整西语文本，勾选其他商品图，再放入原生图片预览。
- 多商品：先列出候选，由用户选择，再生成草稿。多类别：合并为一份草稿。
- 涉及价格：带标准售价作为可修改参考。物流费或手续费不拿商品售价代替；即使已开启自动回复也不自动发送金额。
- 忽略只结束该消息的待处理提示，已经放入原生输入框的文字由用户自行处理。
- 同一条消息不因切换聊天、刷新或滚动历史重新生成/自动发送。翻译或配置失败后的重试须用户明确操作。

### 自动回复

全局自动开启后，可以处理未打开聊天的新消息。发送使用来源聊天模型，不依赖当前打开的聊天，也不会写入当前 A 的输入框来回复 B。

允许条件：插件启用、全局开启且已确认风险、分类开启、单类别、单商品或不涉及商品、内容完整、不涉及价格、配置未在准备过程中变化。商品自动回复只附封面图。

发送前后台持久化领取记录并检查条件；图片准备完成后再核验一次。每聊天每类别设 60 秒冷却，冷却内转人工草稿；多标签页共享领取和冷却记录以防重复发送。自动发送失败或状态不明不自动重试，提示先查看聊天记录。页面/浏览器必须运行且网络正常；电脑睡眠、页面关闭或接口变化时不保证后台持续服务。

## 6. 代码与本地存储

| 文件/模块 | 职责 |
| --- | --- |
| `src/shared/types.ts` | 商品、多图、支付方式、关键词、业务配置及安全默认值。 |
| `src/shared/storage.ts` | 独立业务配置读写，旧配置保留，串行保存配置。 |
| `src/shared/business-replies.ts` | 本地匹配、回复计划、价格判定、群链接校验。 |
| `src/options/OptionsApp.tsx` | 六个业务 Tab 与编辑表单。 |
| `src/options/TranslationSettings.tsx` | 原有翻译设置。 |
| `src/background/index.ts` | 翻译/关键词请求、串行消息领取、发送权限、冷却及上下文。 |
| `src/content/business-replies.ts` | 按聊天排队、缓存、草稿辅助栏、消息状态与页面动作。 |
| `src/page/business-adapter.ts` | 新消息订阅、聊天归属、原生文本/图片草稿、媒体发送。 |
| `src/page/business-drafts.ts`、`hooks/send.ts` | 本聊天业务草稿标记，防止重复翻译，记录手动发送完成。 |

存储键：`config` 保留原翻译配置；`businessData:v1` 保存独立业务配置；`waTranslate:business:message:*` 保存消息状态与去重记录；`waTranslate:business:translation:*` 保存译文缓存；`waTranslate:business:cooldown:*`、`context:*` 保存发送间隔与短期对话上下文。

图片以经过格式和大小检查的 Data URL 存在扩展本地，不写任意磁盘路径，不随配置上传。新增 `unlimitedStorage` 权限用于本地商品图片和历史，仍需磁盘空间；存储错误会提示。卸载扩展或清空扩展数据会删除这些资料。

AI 仅用于实际需要的消息/回复翻译与主动请求的商品关键词建议，使用用户当前配置的服务商和 Key。支付收款正文若选择中文，也会提交给该服务商翻译；填写西语则直接使用。

## 7. 加载与集中验收

### 加载

1. 执行 `npm run build`（或 `pnpm build`），产物为 `dist/`。
2. Chrome 的扩展管理页面重新加载原来指向这个 `dist/` 的扩展，然后刷新 WhatsApp Web。保留同一安装以保留本地历史和设置。
3. 从插件的“打开设置”进入六个 Tab，填写商品及支付正文。所有自动开关初始关闭。

### 用户验收清单

- [ ] 原翻译设置、API Key 和已有聊天记录仍保留。
- [ ] 新建商品，添加多图、排序/换封面、设置价格/币种，保存后列表显示正确；重复名称出现提示。
- [ ] 搜索名称与型号；编辑/停用/删除商品；刷新后资料仍在。
- [ ] 关键词绿色启用、灰色停用；停用不匹配；AI 建议确认并保存后才参与匹配。
- [ ] 支付说明为空时不发送；填好默认银行方式与 OXXO 后，普通支付问题用默认方式，付款上下文中的“不方便”提供备用选项，选择后发送详情。
- [ ] 中文回复生成西语；西语正文直接使用；编辑西语草稿后发送时不重复翻译。
- [ ] 物流回复包含发货后时效、物流方式与发货安排；信任回复可选附上体验群说明和正确链接。
- [ ] 在 A 中等待 B 新消息：默认模式不处理 B；打开 B 后生成 B 草稿。输入框已有字时不覆盖。
- [ ] 商品封面进入原生待发送图片预览；勾选其他图后可调整附件；关闭预览或失败时可手动恢复草稿。
- [ ] 每个新消息只处理一次，翻看历史、引用旧文字和自己发送内容不产生新回复。
- [ ] 开启自动回复时风险确认可取消；全局与分类均开启后生效；暂停后停止新的自动发送。
- [ ] 自动模式下，B 的新消息在 A 打开时仍只回复给 B，当前 A 不被切换。
- [ ] 价格问题、多商品、多类别合并与缺配置均走人工草稿；准备过程中修改配置或暂停也停止自动发送。
- [ ] 发送失败/状态不明不会重复自动发送，能够看到错误并转人工处理。

自动化回归文件为 `tests/business-replies.test.mjs` 和现有翻译相关测试；真实客户发送与 AI Key 联调未由开发代理代做。本次 `npm run build` 已通过 TypeScript 检查与生产打包；这不代替真实 WhatsApp 页面验收。

## 8. 接口兼容性

WhatsApp 内部消息集合、发送函数与媒体预览均为非公开接口；版本变化后可能需要适配。没有可靠聊天归属时停止写入和发送，不用联系人显示名称猜测收件人。

接口适配参考主要项目源码：[WA-JS 消息集合](https://github.com/wppconnect-team/wa-js/blob/main/src/whatsapp/collections/MsgCollection.ts)、[WA-JS 媒体发送](https://github.com/wppconnect-team/wa-js/blob/main/src/chat/functions/sendFileMessage.ts)、[whatsapp-web.js 媒体模块](https://github.com/pedroslopez/whatsapp-web.js/blob/main/src/util/Injected/Utils.js)。这些参考不构成 WhatsApp 官方支持。草稿放在原生输入框方便人工检查，也不能保证规避平台账号限制。
