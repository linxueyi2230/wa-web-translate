# 外贸回复功能开发与交付说明

## 1. 目标与首版范围

WA Web Translate 为中国卖家与墨西哥客户提供商品、支付、物流和信任说明的回复辅助。业务回复目标固定为西班牙语；现有双向翻译设置和聊天记录译文功能保留。

首版六个顶部横向 Tab：**设置、商品、支付方式、物流、信任与保障、常用语**。窄窗口可横向滚动标签。商品及业务配置只保存到当前浏览器的扩展存储。不做 Excel/批量导入、SKU 字段、多设备同步、订单定制或售后 Tab。

状态：功能代码已完成；可通过生产构建生成 `dist/`。真实 WhatsApp 页面中的后台新消息、原生图片预览和图片发送需按本文最后的步骤验收。模拟环境结果不能代替真实账号兼容性验收。

## 2. 页面设计与填写规则

### 设置

保留现有母语、对方语言、AI 服务商、模型、API Key、翻译风格及启用翻译功能。一般聊天仍遵循这些设置；外贸业务回复使用固定西语目标。适合当前业务的聊天语言配置为中文与西班牙语。停用翻译插件后，业务消息处理也暂停。

### 商品

列表上方为本类别自动回复开关、所有商品统一使用的内容语言、搜索和新建入口。每行显示封面缩略图、名称、型号、数字价格与币种或报价说明、启用关键词数量、商品启用状态及编辑/删除按钮；列表不展示描述。

编辑页从上到下：

| 区域 | 内容与行为 |
| --- | --- |
| 商品名称 | 必填，首版不单设 SKU。保存同名商品时提示重复，用户可取消或继续保存。 |
| 型号、商品描述 | 可填写，描述不在商品列表展开；填写后在回复草稿中用中文“描述：”或西语 `Descripción:` 单独展示。 |
| 商品图片 | 从本机选择 JPG、PNG、WebP、GIF；每商品最多 6 张。单图默认上限 16 MB，读取到当前 WhatsApp 网页限制后按实际值调整；上传和放入发送流程时均校验。支持缩略图预览、删除、前后排序、指定封面。自动商品回复和人工商品草稿都使用全部已保存图片，封面在前，其余按保存顺序，可在 WhatsApp 原生预览中删减后一起发送。 |
| 价格或报价说明、币种 | 必填，支持多行英文或西语报价，并提供复制／粘贴按钮。纯数字价格附所选币种；文字报价保留原文及换行，不添加标题或币种，自动回复不翻译报价内容。新商品默认 MXN（墨西哥比索），还可选 USD、CNY、EUR；原有价格与币种配置继续有效。 |
| 中文触发关键词 | 标签、添加输入框、AI 建议按钮及待确认建议。 |
| 商品启用 | 停用商品保留资料，但不参与匹配。 |
| 底部操作 | 取消、保存商品。图片读取期间禁用保存；保存失败保留表单并提示。 |

商品编辑内容和关键词在点击保存后生效。切换 Tab 时，未保存的商品编辑会先提示。列表搜索名称和型号；同一条商品代表一个具体型号或规格。所有商品共用一项内容语言，不逐商品识别语言。

### 支付方式

顶部放本类别自动回复开关，其下为中文关键词、回复内容语言、收款方式列表和添加按钮。

- 首次配置预置“银行转账”（默认）与“OXXO”（备用）；**说明正文均为空**，由用户填写。支持新增、删除、修改、启停和指定默认方式。
- 每种方式维护名称与一段收款说明，账号、银行、支付步骤等写在这段说明里。
- 收款说明与商品描述支持原生复制/粘贴，并提供“粘贴”“复制”按钮。粘贴替换选中文字或在光标位置插入；复制优先复制选中文字，未选中时复制整段内容。读取剪贴板只发生在用户点击粘贴时；失败显示错误，不清空现有内容。
- 支付页选择中文且走人工草稿时，先把填写的中文放入 WhatsApp 输入框，不提前调用 AI 翻译。卖家可用中文编辑，点击 WhatsApp 发送按钮后，发送钩子才把最终内容从中文翻成西语，并持久化中文原文；客户只收到西语，卖家本地展示西语消息与确认后的中文原文。正文已是西语时原样发送。系统生成的备用付款方式列表也遵循支付页的内容语言：中文时使用“你也可以使用以下方式付款：OXXO，你想选择哪一种？”并标记为中文草稿，多种备用方式用顿号分隔，OXXO 等方式名称保持原样；西语时使用西语列表。多类别合并规则见下文。
- 中文付款草稿若开启自动回复，则在自动发送前翻译为西语；自动发送条件不满足而转人工时，恢复为中文草稿。翻译、原文保存失败或译文为空时停止发送，提供恢复草稿的入口，不把中文原文发给客户。
- 点击 WhatsApp 发送按钮（或回车发送）后立即隐藏该聊天的插件草稿面板；翻译和发送期间，输入框清空、定时刷新或新消息到达都不会重新弹出该面板。发送成功后结束本条草稿；翻译失败时恢复错误提示与手动插入/复制入口。发送接口报错但无法确认是否已经发出时，提示先检查聊天记录，不自动重试或重新插入。
- 普通付款问题使用已启用且已填写的默认方式；默认内容未填时提示补充，不擅自改用备用方式。
- 默认方式不方便时，先列出已填写、已启用的备用方式名称，客户选定后发送对应完整收款说明。
- “不方便”“其他方式”等泛泛表达只有在最近已发送的付款回复上下文中才适用；该上下文保留 15 分钟并在刷新后继续有效。未发送的付款草稿不会建立此上下文。
- 选择支付方式名称也可参与匹配；预置 OXXO 和银行转账关键词可启停。新增名称应使用客户可识别的名称，并按需补充对应关键词。
- 留空或停用的方式不会提供给客户。

### 物流

顶部放自动回复开关，下面为中文关键词、内容语言、可编辑物流字段和最终回复预览。

| 字段 | 首次默认值 |
| --- | --- |
| 发货后预计送达时间 | 9–12 天 |
| 物流方式 | 中国物流 |
| 发货安排 | 通常当天下午安排发货，如遇到中国的节假日发货可能顺延。 |

命中物流问题后，先说明付款后与财务核实再发货、发货后提供订单号与截图，再补充这三项物流信息，并提示耐心等待及通过订单号查询物流。默认中文回复为：

> 您付款后，我会与财务核实，确认到账后为您安排发货。
> 发货后，我会把订单号和截图发送给您。
> 发货后预计送达时间：9–12 天。
> 请您耐心等待。您也可以通过订单号实时查看物流信息。
> 物流方式：中国物流。
> 发货安排：通常当天下午安排发货，如遇到中国的节假日发货可能顺延。

预计时间、物流方式和发货安排仍取自用户配置，预览与实际草稿共用同一拼接函数。旧版未修改的默认发货安排升级为中国节假日说明，其他自定义安排保留。预置“怎么发货”，已有启用的“发货方式”也兼容“怎么发货／如何发货”，停用的词不参与匹配。单号、订单截图和物流图片由卖家在 WhatsApp 手动发送，不预录入该页面。选择中文时默认展示中文草稿预览，确认发送后才翻译为西语；通过“生成西语预览”按钮可按需查看译文参考，不替换中文草稿；西语内容直接预览。信任页的邀请介绍和链接也包含在同语言预览中。

### 信任与保障

页面放自动回复开关、中文关键词、内容语言、付款与发货说明、可选客户群邀请链接、是否附带邀请和回复预览。

默认正文：**收到付款后我们会先核实，确认到账后才会安排发货。** 不加入售后承诺，也不重复物流时效和发货安排。

启用群邀请后，拼接顺序为：付款核实说明 → 客户体验群介绍与加入隐私说明 → 单独一行群链接。邀请介绍遵循信任页的内容语言，选中文时用中文供卖家确认。客户自行点击加入。链接必须是有效的 HTTPS WhatsApp 群邀请链接；无效时提示补充，停止这类发送。付款凭证、实际单号和截图仍由卖家手动发送。

### 常用语

默认列表为空，支持添加多条常用语，以及编辑、删除和独立启用／禁用。每条填写管理标题、回复内容、中文或西语内容语言及至少一个触发关键词。标题仅用于管理，不加入发送内容。添加成功后显示为一行，展示标题、内容、语言、启用关键词数量及启用状态；内容和标题必填，关键词可以增删改或独立启停。新建条目默认开启，保存后生效，没有常用语总开关。列表、编辑器及关键词启停均使用滑动开关，明确显示“已开启／已关闭”；没有启用关键词时提示补充。

启用且命中任一关键词时自动回复；禁用条目、停用关键词及未完整填写的条目不参与匹配，也不生成人工草稿。中文内容使用现有译文缓存和发送时翻译流程；西语直接发送。多条命中按列表保存顺序拼接，每条只加入一次。客户原文和中文译文都可匹配常用语关键词；同一条同时命中多词或两种文本也不重复加入。

常用语中的常见问候关键词“你好／您好／嗨／哈喽／Hola／Hello／Hi”互相匹配，避免译文措辞变化导致漏触发。拉丁词仍要求完整词，中文问候别名只在句首匹配；普通自定义词沿用原匹配规则。单独的问候消息（含外围标点或表情）本地识别后直接匹配，无需先调用模型翻译来信；包含其他问题时仍完整翻译、匹配并合并相关业务回复。中文回复内容照常提前翻译、保存原文及核实发送结果。

同时命中业务模块与常用语时，按商品、支付、物流、信任、常用语顺序合并为一份回复。所有相关业务分类开关开启、命中常用语保持启用且资料完整时自动发送，否则按已有业务规则转人工。只有常用语命中时，仅由各条常用语的启用状态决定自动发送。

### 分类自动回复

自动回复 Tab、总开关及分类汇总入口已移除。商品、支付、物流、信任各自在本页面管理自动回复开关，分类开关开启即生效；翻译插件暂停时仍停止业务处理。旧版总开关及风险确认字段不再参与控制，旧配置保留分类偏好；上次停在旧自动回复 Tab 的设置页会打开“设置”。

- 四个分类开关首次都关闭，关闭分类时保留原有人工草稿流程。
- 插件、分类、商品、支付方式、群邀请、常用语和关键词的启停均采用显眼的滑动开关，绿色为开启、灰色为关闭，并显示文字状态。支持键盘操作；分类和常用语列表开关直接保存，商品和常用语编辑器内开关随表单保存。
- 页面明确显示自动发送生效、人工草稿或等待启用插件，保存失败时恢复实际保存状态。
- 关闭相关分类或禁用常用语、修改配置时停止尚未点击的任务；准备图片及实际发送前再次复核配置。
- 报价及多类别合并回复允许自动发送，须开启所有命中业务类别的开关。多商品无法确定型号、内容不完整或任一相关业务开关关闭时转人工处理。

## 3. 关键词编辑

商品、支付、物流和信任类别用同一套关键词操作：滑动开关启停，铅笔修改，独立 × 删除。输入后按回车或点击添加；重复词提示。停用保留词条，重新启用后参与匹配。

商品新建时带常见信息、图片、型号、报价问题关键词，用户可修改。点击“根据商品资料生成建议”才调用已配置模型，将商品名称、型号和介绍作为数据提交；不因每次编辑自动调用。建议默认为勾选状态，必须点击“加入已启用关键词”并保存商品才生效。生成过程中商品资料改变时，丢弃过时建议。

支付、物流和信任类别预置中文常用词，无需模型生成；用户可自行增删改和启停。泛泛付款词受付款对话上下文限制。

匹配规则：对客户**新消息的中文译文**进行匹配；中文按短语，拉丁字母按完整词，忽略大小写并规范化全半角。单词命中一次即可产生候选；同一规则多个词命中只生成一份回复。这些业务类别不对客户原文再跑一套规则；常用语同时匹配客户原文与中文译文，使用相同的短语／完整词规则。不读取引用消息正文来触发。

## 4. 翻译与拼接

1. 客户消息先得到中文译文，再进行本地关键词匹配。单独的常见问候可在本地识别，不调用来信翻译；包含其他问题的消息仍完整翻译。能用既有中文翻译缓存时复用；相同请求共享进行中的翻译，不为关键词另调用模型。
2. 每个业务模块由用户明确选择源语言。商品、报价、支付、物流、信任与保障的人工草稿统一遵循源语言：选中文时先以中文放入 WhatsApp 输入框或原生图片说明，卖家确认、编辑后点击发送才翻译成西语；选西语时直接用西语，不调用语言识别。商品源语言全局统一。中文人工草稿的生成与文字同步不请求中文到西语的翻译；自动回复也按配置源语言填入原生草稿，提前缓存西语内容；点击原生发送后才使用缓存译文，保存准确中文原文且不重复请求模型。转人工时保留可确认的源语言内容。
3. 纯商品询价（如“多少钱”“这个型号多少钱”“价格是多少”）只生成报价文字，按开关自动发送或提供人工草稿。数字价格按模块语言使用“价格：数值 币种”或 `Precio: 数值 币种`；英文／西语文字报价直接使用原文，保留换行，不添加标题或币种，自动发送不改写报价内容。不拼接名称、型号、描述，不附图，也不调用这些商品字段的翻译。如果同时询问商品信息、图片、型号详情等，则保留完整商品信息并带上价格；同时命中支付、物流或信任类别时，按请求合并对应回复，不额外补充未询问的商品字段。价格意图与附图规则在本条消息的处理记录中保存，多商品选择后也沿用本条询问的规则。
4. 商品信息回复的名称和描述按商品内容语言形成可确认的人工草稿。名称、型号、价格（询价时才包含）、描述按顺序用逗号加空格分隔；型号与价格数字/币种保留原样，不单独请求翻译。文字报价作为独立段落放在商品介绍之后，不压平换行，也不在报价尾部补标点；后续类别用空行分隔。数字字段标题按最终草稿语言选择中文“型号／价格／描述”或西语 `Modelo / Precio / Descripción`。非空描述始终包含；即使与名称相同，也不省略描述字段。商品字段内部换行在写入前转换为逗号分隔，避免原生编辑器压平字段。
5. 多类别回复按商品、支付、物流、信任、常用语顺序，以句末标点加空行拼接成一份回复，全部相关开关开启时自动发送，否则提供人工草稿，前段没有句末标点时补中文句号或西语句点。商品字段用中文逗号或西语逗号加空格分隔，已有逗号、句号时不重复追加；不只依赖换行，即使原生输入框压平换行，各段仍有标点分隔。西语备用方式以逗号列出，选择问题前使用句点和空格。链接末尾不加标点，保持原链接并用空格和换行隔开后续文字。命中类别全部选西语时使用西语草稿；只要其中一类选中文，整份草稿使用中文供卖家确认，原有中文部分保持原文，只有已经填写的西语部分按需翻回中文。最终点击发送才把确认后的整份中文翻为西语。群链接由提示词要求保持原样。预览与实际草稿共用段落拼接规则。
6. 中文固定回复按文本、源/目标语言、服务商、模型、翻译场景提示词和翻译风格缓存；修改这些内容后使用新的缓存键。
7. 已准备的西语草稿及其在原生输入框中的编辑内容注册为本聊天的业务草稿；发送钩子不会再翻译一次。所有类别的中文人工草稿保存 `draftLanguage: zh-CN`，编辑时保留此语言标记，点击发送才翻译；该标记与聊天和客户消息 ID 一起核对，不依赖当前翻译设置中的母语猜测。刷新页面后，只有来源聊天和输入框文字唯一匹配待处理记录时才恢复该草稿的语言标记。
8. 商品格式在写入前就确定，原生文本框或图片说明框只执行一次文本写入。写入失败时提示人工检查，不再以换行/逗号回退方式重复替换，也不追加第二份回复。输入框已有内容时不追加；同一动作 ID 复用执行结果，同一草稿已在原生界面时不再插入或重复附图。

### 聊天译文复制与付款语义

- 聊天消息下方的本地译文和已保存原文是可选中的只读文本，不展示额外复制按钮。显式设置 `user-select: text`、`-webkit-user-select: text` 和 `pointer-events: auto`，允许拖动选择、快捷键复制和浏览器右键复制。译文区的选择手势不会冒泡给 WhatsApp 的消息操作；在窗口捕获阶段处理选中本地正文的原生 `copy` 事件，把选中片段写入该事件的剪贴板数据，避免父消息操作替换为客户原文。此操作不调用异步 Clipboard API，不需要额外读取剪贴板，不修改聊天输入框。
- 所有翻译请求共用内置的原意保留规则，适用于各 AI 服务商、聊天入站/出站、付款草稿、业务回复和预览。保持否定、时间限定与原因，准确性优先于语气优化；不凭“无法付款”推断经济状况。
- “现在无法支付”保留为当前无法完成付款，例如 `Ahora no puedo realizar el pago.`；“账号太长，支付不了”保留账号长度导致付款失败的原因，例如 `No puedo realizar el pago porque el número de cuenta es demasiado largo.`。西语 `No puedo pagar` 没有经济原因时译为“我无法付款”；明确说钱不够时仍如实翻译，不把所有付款问题一律改成操作失败。
- 银行账号、付款参考号、金额、币种与链接保持原样。规则并不替用户猜测付款失败原因；没有原因时使用中性表达。
- 翻译也要求句子、字段标题和付款选项之间保留清楚的标点与空格，不把商品名称、型号、描述、价格或后续句子直接粘在一起；不在账号、型号、金额或链接内部插入标点。内置规则版本升级后重新取得译文，不复用旧格式缓存。
- 内置规则版本及场景提示词纳入聊天译文与业务译文的缓存键；新规则或保存后的新提示词不复用旧译文缓存，也不删除保存的发送原文。旧业务草稿主动重新生成时，会按完整提示词上下文重新取得中文译文；历史消息重新显示译文不会触发历史自动回复。

### 可编辑的外贸翻译场景

- 设置 Tab 的“翻译场景与提示词”增加“外贸翻译场景”文本框，默认覆盖中文卖家与墨西哥客户的商品、型号尺码、报价、付款、银行转账、OXXO、物流及交易信任沟通。只帮助理解术语和场景，不代答客户、不生成额外报价或保障承诺。
- 场景提示词作为系统提示的一部分，与原有翻译风格一起应用于入站、出站及需要翻译的业务内容。输出语言仍由请求的目标语言决定：西语使用墨西哥客户易理解的表达，英语使用简洁商务表达，不把所有消息强制翻译成英语或西语。
- 场景提示词先在页面编辑，点击“保存提示词”后才写入本地配置并生效，避免每次键入都使历史译文重新翻译。“恢复外贸默认”恢复编辑内容，仍需保存；主动清空并保存则停用额外场景，保留基本翻译规则。原有风格字段保留原配置。
- 老配置没有场景字段时自动继承默认外贸场景；自定义场景一旦保存就不被升级覆盖。场景修改不会更改语言、模型或 API key；提示词保存失败沿用设置页的失败提示。

## 5. 新消息、跨聊天与发送流程

MAIN 页面适配器订阅消息集合的新模型事件，按消息 ID 中的真实聊天归属记录。仅接收本次页面运行中的新鲜客户私聊文本/图片说明；初始化已存在的模型、自己发送的内容、历史加载、群聊和无文字媒体不会触发。新消息订阅独立于当前打开的聊天；全局自动回复开启后，通过原生导航依次打开来源聊天并操作编辑框和发送按钮。

### 默认草稿

B 来新消息、用户当前在 A 时，只保存 B 的待处理记录。打开 B 后才翻译匹配并生成 B 的草稿；A 界面不出现 B 的草稿。

- 原生输入框为空：插入回复；纯商品询价只插入价格文字，隐藏图片选择入口，不打开媒体预览。商品信息回复有图时一次性把全部已保存图片（最多 6 张）放入同一个原生媒体预览，封面在前，其余保持保存顺序。商品文案只写入当前图片说明一次，不逐张重复写入，等待用户检查和删减后一起发送。
- 输入框已有文字：不覆盖，辅助栏保留草稿并提供插入/复制操作。
- 图片预览失败：保留草稿、显示失败原因，允许手动附图或复制文字；不会自动把回复再写入聊天输入框，不会自行发送。
- 辅助栏只在需要选择商品、输入框被占用、插入失败或取消原生草稿后恢复操作时显示。以独立样式的小面板固定在输入框上方，不插入 WhatsApp 聊天布局、不使用商品图或聊天壁纸作为背景；可查看完整西语文本、勾选商品图，或根据当前资料重新生成旧草稿。
- 草稿插入期间、原生图片预览打开时以及文字草稿成功放入输入框后，移除辅助栏，只保留 WhatsApp 原生编辑界面。关闭图片预览或手动清空文字后，再展示仍待处理的恢复操作；不会自动重新插入本条。右上角“×”或“忽略此条”可关闭本条提示。
- 商品草稿的原生预览左下角保留一个小型“查看草稿”入口，默认收起。点击后按需展开编辑面板，× 或“收起草稿”仅收起面板，不忽略消息、不关闭原生预览；点击发送后入口和面板一起移除。纯文字商品草稿的入口放在输入框上方，避免遮挡输入框操作。
- 编辑面板按草稿实际语言显示“中文草稿（确认发送时翻译）”或“西语草稿”，提供文字编辑、最多 6 张商品图片的勾选、全选、只选封面和“同步所选图片”。文字停止输入 450 毫秒后自动同步，也可点击“立即同步文字”；输入法组字完成后才启动同步。同步时不重新调用翻译，保留输入光标；连续修改会在当前动作结束后同步最新内容。
- 中文商品图片草稿在粘贴整组附件前安装媒体准备／发送钩子，为每个附件保存来源聊天、客户消息 ID 与中文语言标记。卖家点击原生发送后，读取实际提交的每张图片说明，只在此时翻译并保存准确原文；空说明不翻译。说明翻译或原文保存失败时停止该说明的发送，不降级发中文；发送状态不确定不自动重试。无法安装媒体钩子时停止中文图片草稿插入，提示先发送中文文字草稿后再手动附图。
- 同步文字前核对来源聊天、客户消息 ID 和原生草稿的当前文本，原生内容已有新修改时停止覆盖，并保留面板中的编辑内容。选择其他无配文图片时，先在原生预览中选回带商品说明的图片，再同步文字，避免把整段商品说明重复写到每张图上。
- 图片勾选完成后点击“同步所选图片”，一次替换当前预览的附件。例如勾选 2 张时新预览使用这 2 张，不在原有附件后追加一组；文字一并保留。取消所有图片时转为普通文字草稿。更换图片会根据商品保存的原图重新建立预览，裁剪等原生图片编辑应在图片选择同步后进行。
- 图片更新前先校验数量、格式和大小，再只关闭本条业务草稿对应的原生预览；找不到关闭入口、遇到原生确认提示或插入失败时停止重复操作，提示人工处理，并保留编辑面板中的文字和图片选择。整个同步流程不触发发送，最终仍由卖家点击 WhatsApp 的发送按钮。
- 切换多图预览的缩略图时，追踪原生图片说明框的替换，不把这种替换判作整个预览关闭；其他无配文图片也仍属于本条草稿，不弹出第二套编辑界面。图片预览等待最多 10 秒，带图片的插入动作等待最多 20 秒；超时不自动重复附图。
- 商品信息、报价、支付、物流、信任与保障及合并草稿统一采用发送生命周期，按来源聊天与客户消息 ID 标识。点击原生发送按钮即隐藏本聊天的插件辅助栏、编辑面板及“查看草稿”入口；通过文字发送钩子发送（包括回车发送）也在翻译开始前隐藏。发送期间停止文字/图片同步并取消待保存编辑，不因为原生编辑框清空而重新显示草稿。中文、西语、单图、多图及空图片说明都适用。
- 文字和图片发送接口成功返回或匹配的新图片消息确认发送后，结束本条草稿并持久化已发送状态。迟到的预览、编辑、RPC 或存储更新不能恢复已完成的草稿；即使最终状态保存失败，本页面也不会重新插入该已发送草稿。完成信号按客户消息 ID 清理，不清掉同聊天的新草稿。失败时显示错误与人工恢复操作，状态不确定时先检查聊天记录，不自动重试。
- 图片发送只关联插入草稿后新出现的、同聊天且说明文字匹配的发出消息 ID；插入前已有的相同图片说明不计作本次发送。刷新时可根据对应客户消息之后的已发送文字/图片说明修复旧版本留下的待处理状态，缺乏对应消息证据则保留人工处理。
- 多个待处理草稿在辅助栏显示数量及当前客户消息时间，并提供“查看下一条草稿”。原生界面已有一条业务草稿时，其余草稿排队，处理完当前草稿后再展示，避免同时弹出两套编辑界面。
- 多商品：先列出候选，由用户选择，再生成草稿。多类别：合并为一份草稿。
- 涉及价格：使用已填写的数字价格或文字报价，按商品自动开关发送；只询问商品价格时不附带商品详情或图片。物流费或手续费不拿商品售价代替；已配置的物流或其他回复即使包含金额，也可按相应开关自动发送。
- 忽略只结束该消息的待处理提示，已经放入原生输入框的文字由用户自行处理。
- 同一条消息不因切换聊天、刷新或滚动历史重新生成/自动发送。翻译或配置失败后的重试须用户明确操作。
- 客户再次发送相同文字但消息 ID 不同时，作为新消息独立匹配和生成草稿；翻译缓存只复用译文，不抑制新的消息触发。商品的“产品信息/商品信息/产品详情/商品详情”关键词兼容“产品的信息”“产品的更多信息”等有限语法变化，仍需对应关键词已启用，不增加 AI 调用。

### 自动回复

对应业务分类开启或命中已启用的常用语后，客户新消息按后台持久化的到达顺序排队。先打开来源客户聊天，填入 WhatsApp 原生输入框或图片说明，校验收件人、文本和附件，再点击本条回复的原生发送按钮。原生界面串行操作；翻译准备可并行，但后到的消息不能越过仍在准备的前一条。人工草稿不占自动队列名额，仍等待卖家打开来源聊天确认。队列结束后保留最后处理的聊天。

允许条件：插件启用、所有命中业务分类开启、命中常用语均启用、单商品或不涉及商品、内容完整、配置与翻译上下文未变化。报价、物流含运费、物流与信任保障合并等均使用相同条件。商品信息回复发送全部保存图片，最多 6 张，封面在前，其余保持保存顺序；纯询价仍只发文字。

- 连续空闲 5 秒后恢复：仅真实的键盘、点击、触摸、滚动和输入法操作重置计时；同步的插件插入、原生导航及自动点击不算人工操作，原生导航导致的滚动也不计为人工滚动。
- 普通自动回复填入原生编辑框并核验通过后立即点击发送，不再人为追加五秒等待。原生编辑器因程序写入而延迟发出的、内容与本条预期完全一致的 `input` 事件，不当作人工修改；真实编辑仍转为人工确认。输入后发送按钮可能要等一次界面更新才替换语音按钮，最多等待五秒就绪；嵌套的发送按钮与外层同名包装视为一个控件，只点击一次。
- 移除原有同客户、同类别六十秒冷却；客户再次发送的新消息仍按关键词与开关正常自动处理。去重以消息 ID、原生队列占用权和 `queued → sending → sent` 状态转换为依据，不因冷却将新的普通问题降为人工草稿。
- 输入框有未发送文字、原生图片预览尚未结束、插件草稿编辑打开或正在同步时，保持暂停。对自动生成的原生草稿进行人工操作后，本条转为人工确认，保留编辑内容。
- 手动切换聊天、关闭开关或修改配置时停止尚未点击的任务；未插入的任务可以继续排队，已插入的任务转人工。手动关闭的分类开关或常用语不会在五秒后自行开启。
- 原生操作开始前取得跨标签页占用权，保存所属页面、随机令牌及 30 秒有效期，每 5 秒续期。发送授权验证消息所属页面、令牌、配置及单条消息的发送状态；写入前核验发送授权，点击前再次复核授权、聊天、文字及整组附件。失去占用权时停止旧任务。
- 自动回复不直接调用文字发送或图片发送函数，不在原生流程失败后改用发送 API。原生导航只按稳定聊天标识打开聊天，使用当前版本的 `WAWebCmd.Cmd.openChatBottom` 调用约定；导航或原生发送监听不可用时转人工。
- 点击不是发送完成：原生发送返回后检查明确的 `OK` 结果；只有排队结果时，检查对应聊天、本次新消息 ID、文字/图片说明以及至少为 `SENT(1)` 的发送 ACK。`CLOCK(0)` 不算已发送，错误状态不当作成功，无法唯一关联的同文消息不作为完成依据。发送确认最多等待 45 秒，整个页面动作最多等待 150 秒；失败或状态不明转人工检查，不重复点击。跨客户切换要等上一条确认完成。迟到的异步发送在发送授权撤销后不能再通过旧授权；迟到的成功信号可结束相应草稿。
- 自动图片组按实际发送准备对象记录逐张确认，整组共享一份生命周期和队列占用权；其余图片允许空说明，第一张成功不会清除草稿归属。所有预期图片都有明确成功结果或对应新消息的发送 ACK 后才结束任务。重复准备对象复用原发送结果；同一消息 ID 不用于确认两张图片。部分失败或无法明确关联时转人工检查，不重发整组。
- 未发送的中文草稿保留中文；提前准备的西语译文仅在原生发送时复用，并保存准确原文。原生编辑内容变化后不使用旧的缓存发送授权。已发送草稿隐藏，后续客户新消息独立处理。
- 自动客服静默处理，不在 WhatsApp 页面添加状态框、排队计数、待确认计数或暂停按钮。设置页只在各分类及常用语条目中管理启用状态，没有自动回复 Tab、分类汇总或总开关。后台状态快照仅用于诊断。旧人工草稿不在自动模式下自动填入；自动发送失败的记录不转成自动插入任务，也不自动重发。无法明确对应商品、缺少配置等人工例外保留原有确认流程。
- 原生文字写入优先走 WhatsApp Lexical 编辑器的粘贴事件；已处理的粘贴只执行一次。旧编辑器使用一次原生编辑命令。不把 `execCommand` 的布尔值或同步 DOM 状态当成最终结果，最多等待三秒异步提交并核对实际编辑内容。写入期间的程序输入事件不会清掉草稿归属，也不会误判为人工接管；真实键盘、粘贴和点击仍触发保护。

页面/浏览器必须运行、保持登录且网络正常。电脑睡眠、页面关闭或接口变化时不保证持续服务。原生按钮自动发送仍属于自动化，不能保证避免 WhatsApp 账号限制。

存储键：`config` 保留原翻译配置；`businessData:v1` 保存独立业务配置；`waTranslate:business:message:*` 保存消息状态与去重记录；`waTranslate:business:translation:*` 保存译文缓存；`waTranslate:business:context:*` 保存短期对话上下文。旧 `cooldown:*` 记录不再参与发送控制。`waTranslate:business:auto-lease` 保存原生队列占用权，`auto-status` 保存内部诊断快照，`arrival-order` 保存跨页面的单调到达序号；这些键与商品配置分开，不使状态刷新改变商品设置。

图片以经过格式和大小检查的 Data URL 存在扩展本地，不写任意磁盘路径，不随配置上传。新增 `unlimitedStorage` 权限用于本地商品图片和历史，仍需磁盘空间；存储错误会提示。卸载扩展或清空扩展数据会删除这些资料。

配置页复制/粘贴依据（2026-10-11 查询）：[Chrome 官方权限列表](https://developer.chrome.com/docs/extensions/reference/permissions-list) 规定 `clipboardRead` 与 `clipboardWrite` 用于通过 Clipboard API 读取及写入剪贴板。原生输入框快捷键复制/粘贴与程序读取剪贴板不同，配置页没有阻止原生复制/粘贴的事件处理；不能仅凭缺少权限就确认原生粘贴失败的原因。新增这两项权限及用户主动点击的按钮，以提供明确可用的入口；若浏览器拒绝权限，显示原因并提示在浏览器中打开插件设置页后重试。所有剪贴板操作都由用户触发，不轮询或后台读取。

图片大小依据（2026-10-11 查询）：[WhatsApp 官方 iOS 分享说明](https://faq.whatsapp.com/425247423114725/?cms_platform=iphone&locale=pt_PT) 列出的图片上限为 16 MB；[网页版官方媒体帮助](https://faq.whatsapp.com/453914586839706/?cms_platform=web&locale=en_US) 未单独列出统一图片字节上限，因此不将 iOS 数值当作所有网页版版本的固定上限。默认按 16 × 1024 × 1024 字节校验，并通过当前网页的 `WAWebMediaGatingUtils.getUploadLimit('image', null)` 读取实际限制，接口参考 [WA-JS 图片上传限制适配](https://github.com/wppconnect-team/wa-js/blob/main/src/whatsapp/misc/MediaGatingUtils.ts)。网页限制缓存在独立的 `waTranslate:media:image-limit` 键中，有效期 10 分钟，网页每 5 分钟刷新缓存；设置页面随限制变化更新提示。没有可用网页值时使用默认值，放入原生预览和自动发送前重新读取当前接口，超过限制则提示压缩并停止本次图片操作。这与 Business Cloud API 的 5 MB 图片规范属于不同发送渠道。

多图依据（2026-10-11 查询）：[WhatsApp 官方网页版媒体说明](https://faq.whatsapp.com/453914586839706/?cms_platform=web&locale=es_LA) 支持一次发送最多 100 张照片或视频，并可为各项添加说明。本插件商品管理与人工草稿限定最多 6 张，单个原生预览可批量处理这些图片。

AI 仅用于实际需要的消息/回复翻译与主动请求的商品关键词建议，使用用户当前配置的服务商和 Key。支付收款正文若选择中文，也会提交给该服务商翻译；填写西语则直接使用。

## 7. 加载与集中验收

### 加载

1. 执行 `pnpm build`，产物为 `dist/`。
2. Chrome 的扩展管理页面重新加载原来指向这个 `dist/` 的扩展；如浏览器提示新增剪贴板权限，允许后继续。重新打开配置页，再刷新 WhatsApp Web。保留同一安装以保留本地历史和设置。
3. 从插件的“打开设置”进入六个 Tab，填写商品及支付正文。分类自动开关初始关闭，常用语列表初始为空。

### 用户验收清单

- [ ] 原翻译设置、API Key 和已有聊天记录仍保留。
- [ ] 新建商品，添加多图、排序/换封面、设置价格/币种，保存后列表显示正确；重复名称出现提示。
- [ ] 搜索名称与型号；编辑/停用/删除商品；刷新后资料仍在。
- [ ] 关键词绿色启用、灰色停用；停用不匹配；AI 建议确认并保存后才参与匹配。
- [ ] 支付说明为空时不发送；填好默认银行方式与 OXXO 后，普通支付问题用默认方式，付款上下文中的“不方便”提供备用选项，选择后发送详情。
- [ ] 商品、报价、支付、物流、信任类别选择中文时，输入框和图片说明先显示中文，编辑时不翻译；确认发送后才翻成西语。西语正文直接使用；编辑西语草稿后发送时不重复翻译。多类别包含中文时整份用中文确认。

- [ ] 面板中由 6 张改选 2 张，点击“同步所选图片”后原生预览只有所选 2 张，文字保留，不追加重复附件；全部取消时改为文字草稿。

- [ ] 聊天页面不显示自动回复状态框、排队数、待确认数或暂停按钮；设置页不显示队列面板和风险确认；关闭相关分类或禁用命中的常用语立即阻止尚未点击的发送。

- [ ] 多条常用语命中按列表顺序合并，每条只加入一次，标题不发送；客户原文或中文译文均能匹配，与业务回复合并时只点击一次原生发送。

## 8. 接口兼容性

WhatsApp 内部消息集合、发送函数与媒体预览均为非公开接口；版本变化后可能需要适配。没有可靠聊天归属时停止写入和发送，不用联系人显示名称猜测收件人。

原生导航的版本边界依据 [WA-JS 原生打开聊天实现](https://github.com/wppconnect-team/wa-js/blob/main/src/chat/functions/openChatBottom.ts)，导航只打开已订阅来源聊天，不用于发送消息。

发送结果结构参考 [WA-JS 原生发送结果枚举](https://github.com/wppconnect-team/wa-js/blob/main/src/whatsapp/enums/SendMsgResult.ts)、[消息 ACK 枚举](https://github.com/wppconnect-team/wa-js/blob/main/src/whatsapp/enums/ACK.ts) 与 [原生媒体准备对象](https://github.com/wppconnect-team/wa-js/blob/main/src/whatsapp/misc/MediaPrep.ts)。这些源码仅用于结果适配，不新增发送 API 调用。

接口适配参考主要项目源码：[WA-JS 消息集合](https://github.com/wppconnect-team/wa-js/blob/main/src/whatsapp/collections/MsgCollection.ts)、[WA-JS 媒体发送](https://github.com/wppconnect-team/wa-js/blob/main/src/chat/functions/sendFileMessage.ts)、[whatsapp-web.js 媒体模块](https://github.com/pedroslopez/whatsapp-web.js/blob/main/src/util/Injected/Utils.js)。这些参考不构成 WhatsApp 官方支持。草稿放在原生输入框方便人工检查，也不能保证规避平台账号限制。
